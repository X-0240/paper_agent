# Phase 0 报告（2026-09-16）

## 一、目标

在冻结现有 50 篇语料的前提下，验证三件事：

1. 现有 88 题基线是否被反向出题泄露虚高
2. 多通道融合/章节聚合/多 query 能否提升证据级 HitRate@5
3. LLM 重排能否救回排序失败的题

## 二、泄露 A/B

同一批论文、同一索引、同一检索器（hybrid, query=原始中文）：

| 出题方式 | 证据级@5 | 样本 |
|---|---:|---:|
| 正向出题（读整篇论文） | 64.3% | 27/42 |
| 反向出题（从 chunk 出题） | 73.8% | 31/42 |

泄露 gap = +9.5pp，低于 10pp 阈值，暂不触发返工；但属于边界值，test 集必须用正向出题。

## 三、检索模式对照（88 题 dev，原生英文 query）

| 模式 | 证据级@5 | 相对 hybrid |
|---|---:|---:|
| vector | 53.4% | -11.4pp |
| bm25 | 54.5% | -10.2pp |
| hybrid（当前基线） | 64.8% | 0 |
| rrf | 61.4% | -3.4pp |
| section 聚合 | 58.0% | -6.8pp |
| multi-query | 58.0% | -6.8pp |

结论：当前瓶颈不是融合方式，RRF/章节聚合/多 query 的简单实现都是负优化。

## 四、排名诊断（88 题，hybrid top100）

|---|---:|

## 六、Phase 0 门槛判定

| 门槛 | 结果 | 判定 |
|---|---|---|
| 88 题同集 A/B Δ≥5-7pp | +5.7pp | 通过（下沿） |

## 七、下一步

1. 数据层：表格/图注/公式结构化切片 + parent-child，目标修复 5 题 top100 外和部分 21-100 名的证据断裂

## 八、成本

2026-09-16 共 208 次 LLM 调用、1.39M tokens、约 2.31 元（含正向/反向出题与重排实验）。

## 九、Cross-Encoder 生产化对照（bge-reranker-v2-m3）

本地部署 `BAAI/bge-reranker-v2-m3`（多语言 Cross-Encoder，2.27GB，无 API 成本），只重排基线失败的 31 题：

| 配置 | 证据级@5 | 增量 | 平均延迟 |
|---|---:|---:|---:|
| hybrid 基线 | 64.8%（57/88） | - | - |
| 英文召回 + 英文重排，候选25，1500字 | 71.6%（63/88） | +6.8pp | 1025ms/题 |
| 英文召回 + 中文重排，候选25，1500字 | 72.7%（64/88） | +8.0pp | 1012ms/题 |
| 英文召回 + 中文重排，候选10，1500字 | 69.3%（61/88） | +4.5pp | 444ms/题 |
| 英文召回 + 中文重排，候选25，800字 | 69.3%（61/88） | +4.5pp | 713ms/题 |

正向题集（42 题，中文检索+中文重排，候选25，1500字）：64.3% → 83.3%（+19.0pp）。

注意：这里的重排只处理“基线已经失败的题”，而生产不知道哪些题会失败，因此 72.7% 和 83.3% 是离线 oracle 上限，不是可部署成绩。2026-09-17 统一 Service 的全量重排和条件重排未通过切换门槛，详见第十二节。

结论：

1. LLM 重排不是生产方案（10-20s/题、有 token 成本），Cross-Encoder 本地推理是可行方案
2. 最佳质量配置是“英文 query 召回 + 中文问题重排 + 候选25 + 全文1500字”，88题 72.7%、正向题 83.3%
3. 延迟优化方向：候选降到10（444ms，质量-3.4pp）、fp16/ONNX、更小的多语言重排器、按 top5 分差条件触发、按 query+snapshot 缓存重排结果

## 十、Embedding 方法 A/B（Qwen3-Embedding-0.6B）

用同一份 1593 切片重建独立 FAISS 索引，文档侧不加指令，查询侧按模型官方要求加 `query` 指令；其余条件与现有 BCEmbedding 一致。

| 方案 | 88 题证据级@5 | 正向 42 题证据级@5 |
|---|---:|---:|
| BCEmbedding + hybrid | 64.8%（57/88） | 64.3%（27/42） |
| Qwen3-Embedding-0.6B + hybrid | 58.0%（51/88） | 59.5%（25/42） |
| BCEmbedding + bge Cross-Encoder | 72.7%（64/88） | 83.3%（35/42） |
| Qwen3-Embedding-0.6B + bge Cross-Encoder | 62.5%（55/88） | 85.7%（36/42） |

88 题配对诊断为：两方案共同命中 52 题，仅 BCEmbedding 命中 12 题，仅 Qwen3 命中 3 题，净少 9 题。Qwen3 只在正向 42 题重排后小幅领先 1 题，但主口径下降 10.2pp，不支持替换生产 embedding。结论是模型新不代表适合当前中文问题、英文论文和证据级目标；该 A/B 是方法验证，不是版本升级任务。

## 十一、方法优先级结论

| 层级 | 方法 | 判定 |
|---|---|---|
| 保留 | 章节感知切片、BM25+向量混合召回、本地 Cross-Encoder、证据级 HitRate@5 | 当前业务收益和工程成本匹配 |
| 下一项 | 表格/图注/公式结构化切片、章节/父文档上下文注入、parent-child 检索 | 直接针对证据断裂和跨段语义丢失，属于数据处理根因修复 |
| 有条件验证 | 更强 reranker、HyDE、late chunking、RAGAS/DeepEval 次级指标 | 必须先在冻结 dev 集做同口径对照，不接受只凭模型知名度接入 |
| 暂不引入 | GraphRAG、RAPTOR、ColBERT/SPLADE、替换向量库 | 当前 150 篇规模下复杂度和维护成本高于可验证收益 |

改造判断只依据数据质量、检索效果、可靠性、延迟、成本和可维护性，不依据依赖版本新旧。

## 十二、统一 RetrievalService 与可部署 query 验证（2026-09-17）

### 统一实现

建立唯一 `RetrievalService`，`rag_tool`、`tools.search_papers`、`web_search` 和 `evaluation.Retriever` 全部委托同一召回实现；索引元数据增加稳定 `chunk_ids`。查询生成使用 DeepSeek 非思考模式、单次请求、3 秒超时和独立预算预留。

### 关键结果

| 配置 | 88题证据级@5 | 说明 |
|---|---:|---|
| Service 原中文 query，Top5 | 34/88=38.6% | 统一实现基线 |
| 普通直译 English query，Top5 | 54/88=61.4% | 离线query |
| 检索专用 English query，Top5 | 55/88=62.5% | 离线query |
| 检索专用 query + Top50 全量中文重排 | 51/88=58.0% | 重排伤害原命中 |
| English query + Top50 全量英文重排 | 57/88=64.8% | 只比粗排+1 |
| 粗排分数与重排分数融合最优 | 59/88=67.0% | 仍未达到75% |
| 分差阈值0.1条件重排 | 53/88=60.2% | 可见分差不能识别失败题 |

离线“只重排基线失败题”可到 68/88，但该条件使用了 ground truth，不能作为生产触发规则。结论：

- 统一检索链路已完成，查询生成能力可用，但默认关闭
- Top50和条件重排当前不能切换生产
- 75%目标没有达成，对外材料不得引用离线77.3%作为生产结果
- 下一步应解决重排校准/触发或引入更强的候选精排，不得继续用离线oracle包装提升
